# Identity and Addressing

Status: Accepted
Related RFCs: RFC-0005 (primary), RFC-0003, RFC-0004
Related ADRs: ADR-0001, ADR-0006

## Purpose

Defines how entities are identified, named by humans and addressed on the command line in the MVP.

## Identifiers

| Entity | Format | Example |
|--------|--------|---------|
| Artifact | `art_<ULID>` | `art_01J9Z3K8M2Q7X4V6B5N1R0T8WD` |
| Relationship | `rel_<ULID>` | `rel_01J9Z3KQ0A1B2C3D4E5F6G7H8J` |
| Repository | `repo_<ULID>` | `repo_01J9Z3JX9T8S7R6Q5P4N3M2K1H` |
| Event | `evt_<ULID>` | `evt_01J9Z3KRA0B1C2D3E4F5G6H7J8` |

Rules:

- A ULID is 26 characters of Crockford base32, uppercase. The prefix is lowercase and followed by `_`.
- Identifiers are generated by the implementation, never chosen by users, and never change (RFC-0005 immutability).
- Identifiers contain no path, URL or storage information (RFC-0005 storage independence).
- ULIDs embed a timestamp so ids sort by creation time. This is an implementation convenience for listings; **no code may parse meaning out of an id** (RFC-0005 opacity). The model crate does not expose the timestamp.
- Id generation is injected (`IdGenerator` in `functor-core`). Within a process, generation must be monotonic so two ids created in the same millisecond still sort in creation order.

## Slugs

A slug is a human-friendly alias for an artifact.

Grammar: `[a-z0-9][a-z0-9-]{0,62}[a-z0-9]` or a single `[a-z0-9]`. In short: 1 to 64 characters, lowercase ASCII letters, digits and hyphens, not starting or ending with a hyphen, no consecutive hyphens.

Additional rules:

- Unique within a repository, compared byte-for-byte (the grammar is already lowercase, so there is no case folding problem).
- Must not start with `art_`, `rel_`, `repo_` or `evt_`. This makes the id and slug spaces disjoint, so `ArtifactRef` parsing is unambiguous. Underscores are not in the slug grammar, so the prefix rule is already satisfied; it is listed for the benefit of future grammar changes.
- Slugs are **not identity**. They may be renamed with `functor artifact update <ref> --slug <new>`. The old slug is released immediately. The MVP keeps no slug history and does not reserve old slugs: this is a decision, not an open question, and revisiting it needs a new ADR.
- Reserved slugs: none in the MVP.
- Slugs are never used in file names, relationships or events.

## Canonical References

`functor:<entity-type>:<id>` as sketched in RFC-0005.

```text
functor:artifact:art_01J9Z3K8M2Q7X4V6B5N1R0T8WD
functor:relationship:rel_01J9Z3KQ0A1B2C3D4E5F6G7H8J
```

- Entity types: `artifact`, `relationship`, `repository`, `event`.
- The MVP prints canonical references in `--output json` (`ref` fields) and accepts them wherever an id is accepted. They are **repository-local**: no authority or repository component. Cross-repository references (RFC-0009) will extend this syntax and must not change the meaning of the existing form.

## Resolution on the Command Line

Every CLI argument of kind `<artifact>` accepts, in order:

1. A canonical reference `functor:artifact:<id>`.
2. An artifact id (`art_...`).
3. A slug.

Algorithm:

1. Parse the text as `ArtifactRef`. Text matching 1 or 2 becomes `Id` (a malformed id such as `art_xyz` is a usage error, not a slug lookup).
2. Otherwise validate it against the slug grammar. A grammar violation is a usage error (exit code 2).
3. Look the reference up in the repository. If not found, the result is `NotFound` (exit code 3). The message includes the closest slug suggestions (edit distance 2 or less, at most 3) to help typos.

Slugs resolve through the snapshot's slug index, so ambiguity cannot occur in a valid repository. If a damaged repository contains two artifacts with the same slug, `functor` fails the lookup with a `Conflict` error that lists both ids and tells the user to run `functor validate` (rule `V0004`).

Relationship arguments (`<relation>`) accept `rel_...` ids or canonical references only; relationships have no slug.

## Output Conventions

- `text` output leads with the slug. Full ids appear in `create` confirmations, `show`, and `list --long`. The MVP never abbreviates ids and never accepts id prefixes as input.
- `json` output always contains full ids and the slug.

## Test Obligations

- Id and slug parse/display round trips, including the disjointness property (no valid slug parses as an id).
- Monotonic id generation under rapid creation.
- Resolution tests for: id, canonical reference, slug, unknown slug with suggestions, malformed id, grammar violation, duplicate-slug damaged repository.
- Rename keeps relationships intact.
